# C21 optimizer round 2 — FT (Tawan) functional

Date: 2026-08-24
Status: IN PROGRESS (optimizer launched; result NOT yet certified)

## Why this round

`tools/direction2_sdp/joint_c21.py` previously optimized F_B using PAIRS21 = all 21
pairs (i,j) with j>i, including span-one entries (j-i==1). That is the WRONG
functional F_V per Tawan's convention.

Tawan's theorem needs F_T: the pair sum is restricted to **spans r = j-i >= 2**
(span-one pairs dropped); the q_i terms are unchanged.

## What changed (exact diff summary)

New files (copies only; originals untouched):
- `tools/direction2_sdp/joint_c21_ft.py`  (copy of joint_c21.py)
- `tools/direction2_sdp/c21_ft_opt.py`    (copy of c21_opt.py)

joint_c21_ft.py edits:
- Added header comment:
  `# FT variant: span-one pairs removed per Tawan convention (dispute fix 2026-08-24)`
- Added `PAIRS_FT = [(i,j,a) for (i,j,a) in PAIRS21 if (j-i) >= 2]`
- `F_B` now iterates over `PAIRS_FT` (spans r>=2 only) instead of `PAIRS21`;
  q_i terms unchanged.

c21_ft_opt.py edits:
- Import changed to `from joint_c21_ft import ...`
- `theta0` warm-started from `best_c21_theta.npy` via `np.load` if that file is
  present; falls back to the existing hardcoded start otherwise.
- Iteration count `range(120)` -> `range(40)` (bounded time); rng seed (42) and
  scales, filter, bound/eps logging all unchanged.

## How a winner is certified afterwards (NOT by me)

Certification is performed by the in-repo (task-private) verifier, NOT by this
optimizer or by me. The optimizer only produces candidate theta/eps and a bound;
any eps* > 0.00703 (and corresponding bound) must pass the independent Arb
certification in the repo verifier before it counts as a result.
